# Droits et distribution du code d’Ippomed

## Décision appliquée au lecteur courant le 29 octobre 2026

Le propriétaire a choisi explicitement **« Garder le code privé : BodyParts3D uniquement »**. Le lecteur courant retire les imports, catalogues, sélections et chemins Z-Anatomy autorisés ; ses scènes web et natives refusent un dataset non autorisé avant de créer le rendu. Les sources actives sont BodyParts3D 2018, 4.3 et 3.0, avec 2018 par défaut. Les 2 374 nouveaux repères du catalogue régional restent disponibles. La couverture 3D dépend des modèles BodyParts3D réellement présents : les trajets sciatiques, fémoraux et tibiaux auparavant fournis par Z-Anatomy ne sont pas repris dans le nouveau lecteur ; les schémas pédagogiques 2D restent disponibles.

Les modèles BodyParts3D et leurs adaptations conservent leurs notices CC BY-SA 2.1 Japan et crédits DBCLS. La politique autorise leur utilisation dans ce lecteur indépendant sans publier le dépôt applicatif ; aucune nouvelle licence propriétaire globale ni identité de titulaire n’est inventée. Les confirmations de droits et le brouillon ci-dessous restent applicables.

Les anciens assets et notices Z-Anatomy sont conservés pour les APK et lecteurs déjà distribués, ainsi que la révision publique historique de leur code. Le nouveau lecteur ne les importe ni ne les demande. Les garde-fous vérifient les trois références autorisées et l’absence de données de modèles Z-Anatomy dans les bundles web, DOM et Hermes ; le téléchargement du ZIP applicatif reste désactivé. Aucun push GitHub ni changement de visibilité n’est nécessaire à cette publication du site.

La version BodyParts3D uniquement est déployée sous l’identifiant Cloudflare **`1672ff96-f204-4586-acd5-170bfe98e711`**. Les 152 tests, 20 scénarios locaux et huit scénarios publics passent. Le retrait de l’ancien ZIP reste effectif en HTTP 404 ; ses notices et géométries historiques demeurent disponibles séparément. Les nouveaux bundles Android/iOS sont exportés localement ; aucun nouvel APK ou IPA n’est publié. Le [rapport régional](ANATOMIE-REGIONALE.md) détaille les contrôles et la couverture.

Lors du contrôle de cette décision, le HEAD local `d09dbe8d1f273d1f8a7014ef0d3e305eda14f9ea` contient l’extension régionale mais n’est pas disponible sur le dépôt GitHub public inspecté. Le dépôt distant n’expose que `main` à `08598de9eb2a7e864c2ecea2517665e15ea94e83`, sans tag. Les anciennes sources demeurent publiques ; aucun caractère rétroactivement privé n’est annoncé. Les paragraphes suivants décrivent notamment l’audit et le retrait historiques du 28 octobre.

La décision du propriétaire est d’arrêter la distribution volontaire de l’archive complète du site et de préparer des conditions propriétaires pour les prochaines versions, dans la limite des droits effectivement détenus. Elle ne crée ni paiement, ni restriction d’accès aux comptes, ni nouvelle licence sur les composants tiers.

Le retrait de l’archive ne suffit pas à rendre le projet entièrement privé. Le dépôt GitHub et son historique contiennent déjà du code publié ; l’atlas Z-Anatomy soulève également une condition de partage du code décrite ci-dessous. Les conditions propriétaires futures restent un [brouillon](CONDITIONS-PROPRIETAIRES-DRAFT.md), sans titulaire juridique inventé et sans date d’entrée en vigueur présumée.

## Portée des anciennes autorisations

Le texte de [CC BY-SA 4.0, sections 2 et 6](https://creativecommons.org/licenses/by-sa/4.0/legalcode.en), distingue deux effets : les autorisations valablement accordées sont irrévocables, tandis que le titulaire peut arrêter sa propre distribution ou proposer d’autres conditions. Cela ne termine pas les licences antérieures. Les personnes disposant d’une copie autorisée peuvent continuer à exercer leurs droits selon ces conditions. La [FAQ de Creative Commons](https://creativecommons.org/faq/#what-if-i-change-my-mind-about-using-a-cc-license) confirme cette distinction.

Un titulaire peut donc préparer de nouvelles conditions pour des apports dont il maîtrise les droits. Il ne peut pas retirer unilatéralement les droits de tiers, présumer la cession de leurs contributions ou présenter les anciennes versions CC comme devenues rétroactivement propriétaires. L’utilisation commerciale est déjà permise par CC BY-SA : commercialisation et confidentialité des sources sont deux décisions différentes.

## Condition particulière de Z-Anatomy

La [licence épinglée de Z-Anatomy](https://github.com/Z-Anatomy/Models-of-human-anatomy/blob/caf0f6078f2a0ac9e65e81dce042d5a30b65d0f0/License.txt) couvre ses contenus et leurs adaptations. Dans [sa réponse sur la licence d’une application](https://github.com/Z-Anatomy/Models-of-human-anatomy/issues/8), l’auteur demande que le code de l’application soit partagé sous la même licence. Dans [la discussion sur un lecteur propriétaire et un pack séparé](https://github.com/Z-Anatomy/Models-of-human-anatomy/issues/13), il maintient cette position et indique ne pas disposer d’une provenance plus précise de certaines contributions.

Cette position ne doit pas être présentée comme une règle universelle de toutes les licences CC : la [FAQ officielle concernant les logiciels](https://creativecommons.org/faq/#can-i-apply-a-creative-commons-license-to-software) précise qu’elles n’ont pas de conditions spécifiques de fourniture du code source. Le périmètre d’une adaptation et la portée de la position de l’auteur doivent être distingués de ce texte standard. Le projet ne tranche pas cette question juridique en déclarant simplement tout le code propriétaire.

La continuité de la version historique sur une référence publique exacte est conservée lors du retrait de l’archive du site. L’objectif d’un code intégralement privé demeure non établi tant que ce corpus est conservé et que la compatibilité des conditions n’est pas résolue. Une autorisation adaptée du ou des titulaires concernés, une clarification juridique suffisante ou un remplacement autorisé du contenu seraient des éléments à examiner. Aucun remplacement, retrait de fonctionnalité ou contact avec un auteur tiers n’est effectué par cet audit.

## Points à confirmer pour les prochaines versions

Il manque une identité juridique documentée pour le titulaire des futurs apports propriétaires, un périmètre identifié par fichiers ou changements, et les justificatifs applicables aux contributions, textes, schémas et médias concernés. La transition doit également résoudre le cas Z-Anatomy avant de promettre une application entièrement privée. Le [brouillon de conditions propriétaires](CONDITIONS-PROPRIETAIRES-DRAFT.md) matérialise cette intention sans prétendre que ces confirmations sont acquises.
